# DeepSeek Harness — настольная оболочка

Нативное настольное приложение для [DeepSeek Harness](https://www.npmjs.com/package/@deepseek-ai/dsh) (`dsh`). Оно открывает harness в окне и присматривает за локальным рантаймом `dsh web`.

## Требования

- **Linux** (основная целевая платформа; GNOME/KDE, Wayland или X11) — macOS и Windows в принципе работают, но логика рамок окна в лаунчере специфична для Linux.
- **`dsh`**, установленный и рабочий: `npm install -g @deepseek-ai/dsh`
- **Electron ≥ 30** — либо пакет из репозитория вашего дистрибутива (`electron44`, `electron30`, ...), который лаунчер находит сам, либо локальный `npm install`.
- Node.js ≥ 20 (столько же требует сам `dsh`).

## Установка

### Запуск напрямую

```bash
git clone https://github.com/PlazmaBot2000/dsh-electron.git
cd dsh-electron
./bin/dsh-electron          # находит системный Electron, или
npm install && npm start    # использует локальный
```

### Установка как настольное приложение

```bash
./scripts/install.sh
```

Скрипт положит лаунчер `dsh-electron` в `~/.local/bin`, иконки — в тему hicolor, а рядом появится полноценный `.desktop`-файл, так что **DeepSeek Harness** встанет в меню приложений и в док. Откатить всё можно через `./scripts/uninstall.sh` (настройки остаются на месте).

## Клавиатура и меню
| Сочетание | Действие |
|---|---|
| `Ctrl+Shift+R` | Перезапустить harness |
| `Ctrl+Shift+B` | Открыть работающий harness в браузере |
| `F5` / `Ctrl+R` | Перезагрузить окно |
| `F11` | Полный экран |
| `F12` / `Ctrl+Shift+I` | Инструменты разработчика |
| `Ctrl+Shift+L` | Показать файл журнала |
| `Ctrl+Q` | Выйти |

**Правая кнопка мыши** по любому пустому месту интерфейса открывает полное меню действий (Restart, Status, Working Directory, About, Quit...). Поля ввода и выделенный текст оболочка оставляет самому harness.

## Настройка

| Переменная | По умолчанию | Действие |
|---|---|---|
| `DSH_BIN` | авто | Абсолютный путь к `dsh`. Автопоиск идёт по `PATH`, `~/.npm-global/bin`, `~/.local/bin`, `/usr/local/bin`, `/usr/bin` |
| `DSH_NODE_BIN` | авто | Node, которым запускается `.js`-точка входа `dsh` |
| `DSH_HOME` | `~/.dsh` | Дом harness — укажите, чтобы взять отдельный профиль |
| `DSH_ELECTRON_CWD` | `~/AI_workspace`, иначе `~` | Рабочий каталог, в котором запускается harness |
| `DSH_ELECTRON_HOST` | `127.0.0.1` | Адрес, к которому привязывается `dsh web` |
| `DSH_ELECTRON_PORT` | `3080` | Стабильный порт держит origin браузера постоянным, а по нему ключуется localStorage. `0` всегда просит свободный порт у системы |
| `DSH_ELECTRON_ATTACH` | включён | `0` — никогда не подключаться к ещё живому harness из прошлого запуска, всегда поднимать новый |
| `DSH_ELECTRON_ARGS` | — | Дополнительные аргументы к `dsh web ...` (перечисляются через пробел, передаются как argv, а не строкой в шелл) |
| `DSH_ELECTRON_OZONE` | `x11` на Wayland | `x11` — настоящие системные рамки от оконного менеджера; `wayland` — нативный путь |
| `DSH_ELECTRON_BIN` | авто | Какой Electron запускать |
| `DSH_ELECTRON_DISABLE_GPU` | — | `1` отключает аппаратное ускорение |
| `DSH_ELECTRON_TRAY` | включён | `0` отключает иконку в трее |
| `DSH_ELECTRON_DEVTOOLS` | выключены | `1` открывает инструменты разработчика при каждом запуске |
| `DSH_ELECTRON_DEBUG` | выключен | `1` включает подробный журнал |
| `DSH_ELECTRON_SCALE` | `1` | Масштаб устройства, навязываемый Chromium. По умолчанию жёстко 1:1, чтобы плотный текстовый интерфейс оставался чётким, а не растягивался композитором; `auto` возвращает выбор рабочему столу, число (`1.5`, `2`) задаёт масштаб напрямую |
| `XDG_CONFIG_HOME` | `~/.config` | Перемещает всё, что оболочка пишет на диск |

Если `DSH_ELECTRON_PORT` уже занят, оболочка не падает — она просит у системы свободный порт и считает настоящий из вывода harness.

При первом запуске, который поднял harness, оболочка сохраняет его endpoint — URL и launch-токен, открытым текстом, в файл с правами только владельца (`0600`) — в `~/.config/dsh-electron/harness-endpoint.json`. При следующем запуске она читает эту запись: если harness за ней ещё жив и сохранённый токен всё ещё проходит, окно подключается к нему, а не поднимает второй. Чужой (attached) harness оболочка при выходе не убивает, а «Restart Harness» всегда поднимает новый. Если сохранённый endpoint исчез — поднимается новый harness.
